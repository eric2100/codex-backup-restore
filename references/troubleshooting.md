# 匿名故障排除經驗

本文件整理真實還原過程中觀察到的失敗類型；已移除使用者、機器、日期、備份識別碼、實際路徑及執行紀錄。以下名稱是程序／產品識別，不代表任何使用者的環境。

| 現象 | 診斷與修復 |
| --- | --- |
| CLI 已退出，還原仍被鎖定 | 主程序可能叫 `ChatGPT.exe`。用完整執行路徑確認是否屬於 Codex，另查子程序。 |
| 正常關閉呼叫回傳成功，程序卻還在 | 回傳只代表送出請求；重查程序存活與檔案占用，取得授權後精準處理。 |
| App 關閉後背景 worker 消失 | 使用獨立排程，檢查 worker PID、心跳及本次 run id；單靠背景啟動旗標不能證明獨立存活。 |
| 目錄搬移遇到權限錯誤並留下部分搬移資料 | 保留兩側，盤點現況與原始回復副本；不要把半搬移當完整備份。 |
| 同磁碟重新命名也被拒絕 | 檢查實際占用和 ACL；已有完整回復副本時，可採逐檔覆蓋。 |
| Robocopy 回傳 11，Windows 錯誤 32／1224 | 檢查背景外掛 `extension-host.exe` 與資料庫映射；它可能在技能／外掛目錄下執行，關閉主程式未必釋放。 |
| 根目錄資料庫已處理，但巢狀資料庫仍異常 | 找出所有 SQLite 檔案集，連巢狀 WAL／SHM 一併保全與還原。 |
| 顯示大量檔案已複製，使用者仍看不到資料 | 複製數量不能代表整體成功；驗證所有元件、雜湊、資料庫，並另做 App 內功能檢查。 |
| 雜湊及 SQLite 通過，App 功能仍有問題 | 檢查路徑映射、版本相容性、認證、外掛環境及實際聊天／專案狀態；資料層與使用層分開報告。 |

每次修復應根據目前證據。個別環境的固定路徑、程序清單與備份數量不能作為通用還原器的常數。
